Magic Global Support : RESTful API Services: Request and Response parameters are not visible in Open API paths when using the content type "application/json&#8221;.

Created by Vaishnavi Marathe on 01,Sep, 2024

There was a request from a customer where he wanted to Load the  OpenAPI file that includes all parameters like Query, header, cookie, request, and response.

The customer would like to use content-type as application/JSON as it is not visible in the path window.

But while creating RESTful API service and selecting API Definition Method as "Open API" and loading an OpenAPI document into Magic XPI, it retrieves all details, including all paths and parameters defined in the YAML/JSON file.

Yaml File:

The Request and Response tabs in the paths window are used to specify multipart/form-data parameters only and not normal Request/Response parameters.

According to our QA team, the current implementation does not support specifying the application/json content type in the response parameter, as it only accommodates parameters of type multipart/form-data. In the provided YAML file, a parameter with a content type of application/json is treated as a standard parameter rather than one of the multipart/form-data type.

This will be implemented in a future version of the product.
