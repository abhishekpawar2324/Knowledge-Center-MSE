Magic Global Support : How to start Giga-spaces when inconsistent

Created by Amjad Madre on 31,May, 2023

There could be a scenario where the mgxpi-gs, mginfo-gs will start and mirror-gs will start up without error.

If you try to stop and start the GSA again, sometimes the mgxpi-gs, mginfo-gs will start up without error, but the mirror-gs will not start up. (refer to the below screenshot)

 

If you try to stop and start the GSA again, sometimes the mgxpi-gs will start up without error, but the mginfo-gs and the mirror-gs will not start up.

 

 And you are getting the following message in log :

2022-04-26 11:56:04,990 GSM SEVERE [org.jini.rio.tools.webster] - Failed to write file [mgxpi-gs.jar]; Caused by: java.io.IOException: Renaming C:\MAGICX~1.13\Runtime\Gigaspaces\deploy\mgxpi-gs823891104509795521 to C:\MAGICX~1.13\Runtime\Gigaspaces\deploy\mgxpi-gs failed.

2022-04-26 12:03:26,762 SEVERE [com.magicsoftware.xpi.server.spacebridge.spaceservices.Admin] - ; Caused by: org.openspaces.admin.AdminException: Failed building deployment of [C:\MAGICX~1.13\Runtime\.\java\lib\mgmirror-gs.jar]

 

For this we have to check/do the following :

The error appears to be an access rights issue. The user needs to be able to write to the installation directory.

Check the following:

  1. Please start the services with command line.

     Therefore open a cmd with the administrator and navigate to                  

     <InstallationDirectoryxpi>\Runtime\Gigaspaces-xpi\bin and start the "magicxpi-gs-agent.bat" from cmd    

      then try.

  1. In addition,

    Magic xpi requires 8dot3name support when it is installed in a location that contains spaces. Make sure                                  

    that 8dot3name is supported. If 8dot3name is not enabled, you should run the following command as an   

    administrator:

     fsutil 8dot3name set <required installation drive> 0
     For example, to enable 8dot3name on the C drive:
     fsutil 8dot3name set c: 0

You may need to restart your machine for the settings to take effect.

3.1   Also add JRE_HOME path to JAVA_HOME.
        Example:
        set JAVA_HOME=%MAGIC_XPI_HOME%\Runtime\jdk8x64\jre

3.2   Please test the manual running service by running "runwebmonitor.bat" installed Magic XPI using    

        Administrator command line.
        %Installation dir%\Runtime\RTView\magicmonitor\runwebmonitor.bat and then try to start a project   

         from the monitor

  1. Also, make sure the machine has sufficient CPU and RAM as per the minimum requirement for production.

 

 

And still, if it is not working and getting the following  :

2022-04-28 08:36:42,001 GSM SEVERE [org.jini.rio.tools.webster] - Failed to write file [mginfo-gs.jar]; Caused by: java.io.IOException: Renaming C:\MAGICX~1.13\Runtime\Gigaspaces\deploy\mginfo-gs3495666704000217540 to C:\MAGICX~1.13\Runtime\Gigaspaces\deploy\mginfo-gs failed.

 

Then you have to remove Antivirus Software from your machine and check if it works.

 

 

·        Please make sure that the antivirus was not in a place where the XPI server is installed

 

·        Please check if the Discovery/Webster/LRMI port is not used by any other processes by using the following command:

[netstat command("netstat -ano -p tcp").]

 

·        Please disable the antivirus so that it will not arise any issues while deploying processing units(for eg. Magic space, Magic info, Magic mirror)

 

Note: The root cause was the antivirus blocking the deployment and permanently disabling the antivirus will resolve the problem
