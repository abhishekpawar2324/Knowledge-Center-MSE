Created by Amjad Madre on 31,May, 2023

How to avoid High CPU load because of huge size of Activity log

1.1Please set JAVA_HOME in located batch file under the <Magic xpi installation>\Runtime\RTView\magicmonitor\runwebmonitor.bat folder.
e.g
set JAVA_HOME=%MAGIC_XPI_HOME%\Runtime\jdk8x64

1.2 Increase the magic monitor memory.
%MAGIC XPI 4.13 Installation%\Runtime\RTView\magicmonitor\runwebmonitor.bat
e.g
-Xmx2048m -Xms512m

  1. The activity log table number of records and the log level (MonitorLogLevel =* All) can indeed affect the performance. Activity Log messages can now be filtered.
    Please find the screenshot attached. You can remove the unnecessary logs like flow started, Flow component started & other messages.

and/or

2.1. This is totally based on the database performance as well. For this we do suggest customer to limit the activity logs or set it to error level.
Please set the below flag in ifs.ini
[MAGIC_IBOLT]MonitorLogLevel=* ERROR

  1. BLOB variables in Save Message steps can now be saved to the file system instead
    of the database.
    Please set the below flag
    "[MAGIC_IBOLT]activityBlobFileLocation=c:\\temp"
    In your project ifs.ini(Location : <<XPI413_installation_directory>>/Runtime/Projects/ifs.ini).

  2. Microsoft SQL Server Version should be Standard or Enterprise Editions. Version should not be Microsoft SQL Server Express used for internal database.
    Microsoft SQL Server Express has a 10 GB maximum database size and other important limits.
    SQL query to check version: SELECT @@VERSION as sql_server_version

  3. Periodically DELETEs records from the the actlog. like e.g 1week.

  4. We can recommend the customer to use only 1 magic info primary instance and 1 backup(if cluster).
    This will help us to reduce the network transactions and to stabilize the environment.

  5. Restart the monitor service.
