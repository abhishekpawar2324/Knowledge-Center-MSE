Magic Global Support : How to Dynamically Enable/Disable Flows in Magic XPI

Created by Balaji Karagir on 06,May, 2025

Problem:
You want to dynamically enable or disable flows in Magic XPI during runtime. The use case involves receiving a flow ID (which needs to be disabled) through an HTTP trigger. Based on the incoming request, you need to either enable or disable the corresponding flow using Magic XPI utilities.

You would like to automate this behavior so the flows can be turned ON or OFF without requiring manual intervention through Magic Monitor.

Cause:
In Magic XPI, flows are usually turned ON or OFF manually using the Magic Monitor or during development.
But in some cases, you may want to control flows based on runtime inputs—like values received from an HTTP request.
This is useful when you want to manage flows using external systems, change settings without manual work, or handle different environments automatically.

Solution:
To dynamically enable or disable a flow at runtime, follow the steps below:

  1. Receive Flow ID from HTTP Trigger

Set up an HTTP Trigger in your Magic XPI flow to receive the business process ID (bpid) and flow ID (flowid) from an external request. These values will be used to identify which flow needs to be enabled or disabled.

  1. Check Flow Status Using IsFlowEnabled Function

Use the built-in IsFlowEnabled(bpid, flowid) function to check the current status of the flow.

  1. Enable or Disable Flow Using the “Enable Flow” Utility

Depending on the result from IsFlowEnabled, use the Enable Flow utility to enable or disable the specified flow.

  • In the utility configuration:

    • Set Business Process ID to the value received (e.g., 1)

    • Set Flow ID to the value received (e.g., 2)

    • Set the Action to:

      • Disable – if flow is currently enabled

      • Enable – if flow is currently disabled

This will dynamically change the flow’s status at runtime.

Disable – If flow is currently enabled

 Enable – If flow is currently disabled

Example Workflow:

  1. HTTP Trigger Step
    Receives a request containing:

    • bpid = 2

    • flowid = 5

  1. Condition Step:
    Checks if the flow is currently enabled using:

IsFlowEnabled(2, 5)

 

Enable Flow Utility Step:

  • If condition is True → flow is enabled → Disable it.

  • If condition is False → flow is disabled → Enable it.

Magic moniter:

After Disable 2nd Flow of First Business Process.

Additional Considerations:

  • Ensure the flow is not actively running when disabling it.

  • You can add logging steps before and after the action to track changes made.

  • Use data mapping to dynamically pass values to the Enable Flow utility.

Conclusion:
By using the IsFlowEnabled function and the Enable Flow utility, you can dynamically control the status of flows in Magic XPI. This allows greater flexibility in handling runtime decisions based on incoming data, enabling you to build smarter and more adaptive integration flows.
