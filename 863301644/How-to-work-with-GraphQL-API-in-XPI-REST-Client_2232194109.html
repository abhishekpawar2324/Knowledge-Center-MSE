Magic Global Support : How to work with GraphQL API in XPI-REST Client

Created by Amjad Madre on 31,May, 2023

GraphQL is an alternate option to build APIs in REST. It is designed to make APIs fast, flexible, and developer friendly. It can even be deployed within an integrated development environment (IDE) known as GraphiQL. As an alternative to REST, GraphQL lets developers construct requests that pull data from multiple data sources in a single API call.

-So to call the GraphQL API inside the REST Client Component of XPI we need to define the respective configuration.

In the postman you can see “Transaction Sale” API is being set with URL – {{endpoint}}/graphql.

Endpoint value is defined inside variable which is -https://payments.sandbox.braintree-api.com

We can observe here we have a request body under GraphQL in parts, one is QUERY and the other is GRAPHQL VARIABLES.

Here we need to write queries that return data, we need to pass in variables to apply sorting and filtering through our data so that we can see relevant data.

 

-So, to get the whole request body which can pass inside the XPI REST Client Component, we used Fiddler with proxy to capture the graphQL API request.

We can see from the above image that we captured the POST Request with URL, Header content, and Body.

-Under XPI we must pass the Request body we got from Fiddler inside the REST Client component with Following Configuration as per Header content.

Here inside Header Parameter, we mentioned Header Parameter as the current date of API calling because all the header information was already captured in Fiddler except “Braintree-Version”.

In Data.txt we stored the request body which is captured in Fiddler.

In this way, we can access the GraphQL API through XPI.
