Magic Global Support : Isolated fix - NHK : Requirement of modification in xpi Web Service Trigger (WSDL)

Created by Shweta Salunkhe on 17,Dec, 2024

Description

The customer is exposing the Web Service using xpi which accepts 2 XML Document as Input & 1 XML Document as Output.

  • As per above configuration, the customer gets below "Actaul xpi Response" via xpi where "xmlns" i.e namespace is given as "http://magicsoftware.com/wsdl/com/ ....." with no "Namespace Prefix" at the top level tag of response structure.

The WSDL is generated from the outside provider.When they are integrating with magic ,the WSDL gets changed and they are getting the response

structure based on the Magic WSDL strucure.
So,they need to change the response structre as per their WSDL where namespace and namespace prefix gets changed.

In the response structure ,they want the namespace according to the WSDL provided.

==> Actual xpi Response
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
<soap:Header/>
<soap:Body>
<AW0000DATA_Response xmlns="http://magicsoftware.com/wsdl/com/magicsoftware/magicxpi/interface/APT00101/ ">
<ESB_HEADER>
<SEND_INFO>
<SEND_SYSTEM_ID>AD</SEND_SYSTEM_ID>

==> Expected Customer Response
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
<soap:Header/>
<soap:Body>
<ans1:AW0000DATA_Response xmlns:ans1="http://shj.nhk.or.jp/AW/types">
<ESB_HEADER>
<SEND_INFO>
<SEND_SYSTEM_ID>AD</SEND_SYSTEM_ID>

Solution:

%XPI installation%\Runtime-ibiowritter.dll

%XPI installation%\Studio\Extensions\Application-iBolt.dll

%XPI installation%\Runtime\ifclib\webservice-WebService.dll

%XPI installation%\Runtime\EE-Languages.dll - with “en/Languages.resources.dll” and “ja-JP/Languages.resources.dll” subfolders

%XPI installation%\Studio\Extensions\Application-Languages.dll - with “en/Languages.resources.dll, iBolt.resources.dll” and “ja-JP/Languages.resources.dll, iBolt.resources.dll” subfolders

%XPI installation%\Runtime-ifs.ecf

%XPI installation%\xpi_webserver\webapps-webserviceprovider.war

%XPI installation%\Runtime\java\lib-mgxpi-gs.jar

Update the values.yaml imm server image and redeploy the environment -
