Magic Global Support : Troubleshooting Image Pull (ImagePullBackOff) Failures in IMM Deployments

Created by Balaji Karagir on 22,Jan, 2025

Problem:

When deploying IMM (In-Memory Middleware), you see the error “failed to pull and unpack image” during the Kubernetes pod deployment. Although IMM only needs an internet connection during the initial setup, you're still getting the “i/o timeout” error, which usually means a network problem. Kubernetes is unable to connect to your Azure Container Registry (ACR) to pull the image.

Cause:

Initially, when deploying IMM, an internet connection is required. However, once IMM is successfully deployed, it no longer needs an internet connection. The "i/o timeout" error typically points to network-related issues such as firewalls, DNS issues, or problems with the node’s internet access.

In this case, Kubernetes is failing to connect to the Azure Container Registry (ACR) to pull the image.

This can happen due to:

  • Network firewalls blocking access to the registry.

You can use tools like curl or wget from within your Kubernetes nodes to test connectivity to ACR. For example:

curl -v https://devmcsworkspaceacr.azurecr.io

This will help confirm whether the nodes can reach the registry. If the connection is blocked, you'll see a timeout or connection error.

  • DNS issues preventing Kubernetes from resolving the ACR hostname.

  • Loss of internet connection after the deployment script finishes, or the image pull was still trying while the internet was disconnected or slow.

This is more about Kubernetes tools and internet issues.

Solution:

To resolve this issue, follow these steps:

  1. Verify Network Connectivity:

    • Ensure that there are no firewall or DNS issues blocking access to the ACR (http://devmcsworkspaceacr.azurecr.io ).

    • Test network access from the Kubernetes node to the registry, ensuring no packet loss or interruptions.

You can use the ping command to check if your Kubernetes node can reach the Azure Container Registry (ACR) endpoint.

 

ping devmcsworkspaceacr.azurecr.io

 

Expected Result: If the network is working, you should see responses like:

If there's a network issue, you might see errors like "Destination Host Unreachable" or timeouts.

  1. Check Pod Logs:

    • Run kubectl describe pod <pod_name> to get detailed information about the pod. This command will show events, states, and error messages related to the pod’s image pull attempt.

    • Look specifically for any network-related errors or timeouts.

  2. Check for Network Problems:

    • If the problem is a slow or unstable network connection, check the node’s internet access.

    • Try redeploying when the network is stable.

  3. IMM Installer (Air-Gapped) Solution:

    • To resolve this kind of scenario, we have introduced the IMM installer (air-gapped) in 4.14.1.

Version:

  • Affecting Version: XPI 4.14

  • Fix Version: Magic XPI 4.14.1 Windows

 

Conclusion:

By ensuring stable network access and using the air-gapped IMM installer (in version 4.14.1), you can resolve issues related to the "ImagePullBackOff" error. This solution is more network-related, and addressing firewall, DNS, or internet access issues should mitigate the problem.
