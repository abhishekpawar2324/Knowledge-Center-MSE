Magic Global Support : Identification of Memory leak in magic xpi server process and use of the queryCache flag

Created by Amjad Madre on 31,May, 2023

We had the problem of out of memory due to the memory leak. In the investigation Memory leak was found, when we run the scheduler with save message. It is almost 15mb in 6 hrs of execution.

When we capturing the Mgxpiserver.exe process by copyto the clipboard (ctrl+c)on the process and paste in the notepad.
We will need information for this every hour after the project starts memory leak.

Solution:-

There is a Flag you need to magic.ini in [JVM_ARGS]
-Dcom.gs.queryCache.bounded.enable=false

This will help to reduce the memory consumption that you observe for the projects.

However please note you need to restart the projects as changes in magic.ini affects only after the project is stopped and restarted.

Reference bug:-
MXPI-9984

In Other cases,
We saw some increase in memory and execution time after using the flag -Dcom.gs.queryCache.bounded.enable=false.
