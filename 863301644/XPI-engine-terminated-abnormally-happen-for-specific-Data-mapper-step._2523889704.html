Magic Global Support : XPI engine terminated abnormally happen for specific Data mapper step.

Created by Prachi Palande on 01,Apr, 2024

Problem Description:

On execution of specific datamapper step, the XPI engine terminates abnormally.

The datamapper has database in source and destination side. Database used Oracle.

Cause of the issue:

Invalid column name definition on the source DB schema of the specified step.

The Wong definition is likely to have happened due to UI's wrong behaviour that finalized the definition of the column to be invalid.

The following mapper screenshot presents the wrong column definition and as a result, the Generated code suffers from the wrong XPA variable definition.

 

 

 

 

It is true that the column is not connected but once it is selected xpa DSQL will try to insert a value into that column and the XPA program will crash.

The XPI properties for a non-connected column cannot be changed from their default which are StringDate=No and AlwaysUseCustomerPicture=No.

There were cases in previous versions that due to manipulations of connection removal these properties remained in an invalid state like here.

The UI affects the generated code and since Alpha cannot receive values except digits the XPA size is zero.

 

Solution:

In the recreated step the above column has the valid XPA picture, and the data type is Date and not Alpha - check the next similar images for the recreated step.

 

 

 

 

The old step can also be corrected by simply connecting this column and setting the string date and

AlwaysUseCustomPicture to false - and then removing the connection.

OR remove that column from the SQL statement so that it will no longer be part of the XPA generated code data view.
