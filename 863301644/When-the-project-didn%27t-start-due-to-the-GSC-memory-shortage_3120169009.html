Magic Global Support : When the project didn't start due to the GSC memory shortage

Created by Vaishnavi Marathe on 07,Jan, 2025
The customer encountered an issue where the project failed to start due to insufficient memory in the GigaSpaces container. Despite increasing the GSC memory size from 1024 MB to 2048 MB, the following errors persisted in the logs:
mgxpi-gs.1 [1] SEVERE [org.openspaces.events.polling.SimplePollingEventListenerContainer] - [startRequestedWatcher] Execution of event listener failed; Caused by: org.openspaces.core.SpaceMemoryShortageException: Memory shortage at: host: EC2AMAZ-SFLVTG7, container: MAGIC_SPACE_container1, space MAGIC_SPACE, total memory: 2014 mb, used memory: 1580 mb; nested exception is Memory shortage at: host: EC2AMAZ-SFLVTG7, container: MAGIC_SPACE_container1, space MAGIC_SPACE, total memory: 2014 mb, used memory: 1580 mb

This issue is not solely related to the GSC configuration. Other factors such as machine specifications (RAM, processor, and CPU), as well as the number of projects, must also be taken into account.
The memory shortage might stem from project data being stored in Magic Space. To mitigate this, the following steps can be implemented to distribute projects across multiple spaces:

Keynotes:

1. following in the magicxpi_sla.xml file i,e Magic Space:

<os-sla:sla cluster-schema="partitioned-sync2backup" number-of-instances="2"

number-of-backups="1">

**We can increase the Magic Space count according to the Project count.

2. GSC Memory Configuration, You can increase to 2 GB or more.

-Increase the memory of GSC in 'magicxpi-gs-agent.bat' to 'set GSC_JAVA_OPTIONS=-Xmx4096m' on the server.
 
By following these suggestions, the memory shortage issue can be effectively resolved.
