Magic Global Support : False username in SOAP requests

Created by Amjad Madre on 31,May, 2023

Description: 

The customer has created a project in which there are two business processes one is for a German company and the other is for an Austrian company.

Using the same SOAP resource differentiates it with a username but the same password.

Problem: Sometimes a request which should go to the German Praxedo goes to the Austrian. Somewhere somehow the Austrian username comes in the German request or the other way around. That happens then for a few minutes or hours and then it is ok again.

Reference case:  92365

below is the solution :

We checked all kinds of logs to investigate the issue but from the log, we didn't find any suspicious as the customer is checking the above issue in their portal and not in xpi.

At last, we suggested creating different resources for both the business process i.e one resource for a German company and the other one for an Austrian company, and loading the same wsdl url and it worked!!
