Magic Global Support : When the RestFul API trigger response body header content-type set to the 'Application/Json',it throws the error in the browser.

Created by Shweta Salunkhe on 13,Sep, 2024

Description:

In a flow with a RESTful API Trigger in place,when trying to return json in the response body, it throws the error in the browser.
But when check response header in chrome's development tool,then we can see the content-type is "application/xml".(Screenshot of chrome attached)
and also response is showing in the JSON format in the chromes development tool.

In the variable set in the RESTful API Trigger response header, "application/json" is set, but this does not seem to be working.

Solution:

The project level configuration resolves the reported issue. Used the sample project recently attached.

  1. User needs to remove response parameter entry for the Paths defined.

2.'content-type = application/json' property user can update in the flow data step for C.UserString variable.

3.Keep the trigger configuration as is.

4.When we give call after project execution starts through browser as 'http://10.9.6.71:8085/xpiREST/RESTfulAPIzipProject1/RESTfulAPI1/zip/zipcode/0030838', and inspect the result by checking Headers, the 200 OK and expected Content Type observed as:

5.Similar test confirmed by POSTMAN utility too.
