Magic Global Support : SharePoint: Not able to connect using NTLM authentication in Magic XPI

Created by Balaji Karagir on 17,Apr, 2024

There was a scenario where customer was not able to connect to SharePoint Server in Magic XPI when they have used NTLM to connect to the SharePoint Server.

In Postman, they were able to connect SharePoint server using NTLM authentication.

 

Affected Version: Issue observed in XPI 4.7

Fix version: Magic XPI 4.14.1 Windows

 

Fix Description:

Initially in the code we are supporting to NTLM authentication and now with respective changes we are also supporting to NTLMv2 authentication.

 

Solution:

Initially in the XPI we are supporting NTLM authentication and now with respective changes we are also supporting to NTLMv2 authentication from XPI version 4.14.1.

The following 2 possible solutions can be applied here,

  1. Please give the table instead of that view to check the grade of the login employee.

  2. If possible, we can add one extra field in the User master table for "grade" this will help to lesser requests to Postgres db at the login window.

We have workaround for lower versions from XPI 4.7 to XPI 4.14.

Change the group policy setting to minimum.

  1. Network security: Minimum session security for NTLM SSP based (including secure RPC) servers 2. Network security: Minimum session security for NTLM SSP based (including secure RPC) Client from 'Require 128-bit encryption' to 'Require NTLMv2 session security.

some more information on this topic: https://learn.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/network-security-minimum-session-security-for-ntlm-ssp-based-including-secure-rpc-servers

Here are the steps to change the group policy settings for both servers and clients:

  1. Open Local Group Policy Editor:

  1. Press Win + R to open the Run dialog.

  2. Type "gpedit.msc" and press Enter.

  3. This will open the Local Group Policy Editor.

  1. Navigate to the Policy Setting:

  1. In the Local Group Policy Editor, navigate to the following path:

 

Computer Configuration -> Windows Settings -> Security Settings -> Local Policies -> Security Options

  1. Change Minimum Session Security for NTLM SSP based Servers:

  1. Look for the policy setting titled "Network security: Minimum session security for NTLM SSP based (including secure RPC) servers".

  2. Double-click on it to open its properties.

  3. Select the radio button "Define this policy setting".

  4. Under "Options", uncheck "Require 128-bit encryption".

  5. Check "Require NTLMv2 session security".

  6. Click Apply and then OK to save the changes.

  1. Change Minimum Session Security for NTLM SSP based Clients:

  1. Similarly, look for the policy setting titled "Network security: Minimum session security for NTLM SSP based (including secure RPC) clients".

  2. Double-click on it to open its properties.

  3. Select the radio button "Define this policy setting".

  4. Under "Options", uncheck "Require 128-bit encryption".

  5. Check "Require NTLMv2 session security".

  6. Click Apply and then OK to save the changes.

  1. Close Group Policy Editor:

  1. Once you have made the changes for both server and client policies, you can close the Local Group Policy Editor.

  1. Restart the System (Optional):

  1. Sometimes, changes made through Group Policy may require a system restart to take effect. It's a good idea to restart your system to ensure the changes are applied properly.
