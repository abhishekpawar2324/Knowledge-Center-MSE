Magic Global Support : Project Deployment in XPI (Standalone and Cluster configuration)

Created by Amjad Madre on 31,May, 2023

What is deployment?
It is recommended that you deploy Magic xpi projects to a shared folder, accessible by all application servers. Although a shared folder is potentially a single-point-of-failure, with today's storage systems this type of resource is usually highly redundant by itself.
You need to prepare the Server environment while deploying:
To prepare the Server, you must:

  • Create an executable file

  • Take care of the configuration files

  • Copy the entire Project folder (regardless of its size).
    Modify the following project elements to fit the production environment settings (for example, license name, paths, and logical names):
    -The start.xml file
    -The ifs.ini file
    -The shortcuts' reference
    If necessary, modify the Magic.ini file in the production environment to fit the Magic.ini file in the development environment (for example, license names, paths, and logical names, such as the current project and DB_SERVER_NAME).
    There is another way when the project already exists in the production environment and you want to update it with changes that you made to the project while it was in the development environment:
    -Copy the following project elements from the development environment's project folder into the production environment's project folder:
    -The project's ibp file
    -The service.xml and the resource.xml (if changes were made)
    -The ifs.ini file or part of its content (if changes were made)
    If necessary, modify the Magic.ini file in the production environment to fit the Magic.ini file in the development environment (for example, license names, paths, and logical names).

    Deploying an existing Project

  • Stop the Project from the monitor.



  • Take a backup of the existing project.

  • Copy the latest project from Development Area to Production.


  • Copy the configuration files from the Project Config folder to the Project folder.

  • Start the project.


Other Information
Configuring Projects to Start Automatically
You can create a file called projectsStartup.xml that tells Magic xpi to automatically start your projects and servers when the Magic xpi service deploys the Magic Space.
The structure of the projectsStartup.xml file is identical to the structure of the start.xml created under each project.

  • Make a copy of the start.xml file or the projectsStartup.xml.example file, which is located in the config folder.

Make the changes that you want, name it projectsStartup.xml and save it to the config folder.

Sample projectsStartup.xml for the MB project.

This example file configures the following settings:
• Each application server will start one server process/instance.
• APP1 will start 10 workers and will run all the triggers, the Autostart, and the Scheduler.
• APP2 will start 10 workers, without loading any triggers, without running any Autostart flows, and without running the Scheduler.
• Each application server will set its alternateHosts property to point to the two other application servers. This is done to ensure that if one of the hosts is unavailable, the server defined to run on this host will start on one of the other defined hosts.
The shared projects folder is configured using the ProjectsDirPath attribute. Note that you can define the same folder for all application servers, or have each server access a local projects folder.


The startup sequence of the grid is as follows:
• The Grid Service Agent (GSA) is started as a service on each application server that is part of the grid. The Grid Service Agent starts the core grid infrastructure to connect all application servers.
• One of the GSAs that started successfully deploys the Magic Space. This Magic Space contains all Magic-related objects that are shared across the grid.
• The same GSA also deploys the projectsStartup.xml information into the Magic Space, creating a ServerData object for each of the servers. This enables projects to start automatically.
• The GSA receives a command from the Space to run the Magic xpi engines. This is based on the list of ServerData objects that were created in the Space as part of the deployment and automatic startup process.
For each project that is deployed, the first Magic xpi server that starts is responsible for initiating the project's metadata objects in the Magic Space to enable the projects to start.
