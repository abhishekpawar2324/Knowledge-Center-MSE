Magic Global Support : High CPU usage due to the Gigaspaces running with OSHI service

Created by Amjad Madre on 31,May, 2023

During this time we also see some of the GS processes consume High CPU after starting GS grid.


Regarding OSHI-Services, We do see same time severe errors like old and latest logs,
2021-06-17 11:16:14,630 GSC SEVERE [oshi.util.platform.windows.PerfCounterQueryHandler] - Counter \Processor(_Total)% Interrupt Time does not exist to query.

And
WMI service also consumes the CPU.



Solution:

This Flag("-Dcom.gs.oshi.enabled=false") was added in Magic xpi 4.13.1,Which was not present in the installation of Magic xpi 4.13.
Disabling the "OSHI-Service" helps to reduce the CPU usage.

--
In the file - %Installation XPI 413%\Runtime\Gigaspaces-xpi\bin\magicxpi-setenv.bat
set ADDITIONAL_OPTIONS=%ADDITIONAL_OPTIONS% -Dcom.magicsoftware.ibolt.home=%MAGIC_XPI_HOME%\runtime -Dlogback.configurationFile=%MAGIC_XPI_HOME%\runtime\Java\classes\gigaspaces.root.logback.xml -Dcom.gs.oshi.enabled=false


After the use of the OSHI flag.
